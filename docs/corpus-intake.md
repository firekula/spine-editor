# 真实项目语料移交指南（corpus intake）

## 为什么需要你的真实项目

harness 的金标准回归完全由语料决定：官方编辑器导出的每一份 JSON 都是
"官方口径"的样本。真实项目的覆盖面（linked mesh、physics、sequence、
deform 密度、皮肤数量）直接决定后续编辑功能的格式安全网强度。

## 怎么给我

**聊天窗口直接拖文件**（推荐）：单个文件或打包 zip 都行，会进入我的 upload/
目录，我来解包、入库、跑回归。

入库动作（我来做）：放入 `corpus/v3.8/` 或 `corpus/v4.2/`（按导出编辑器的
大版本分目录），然后 `npm test` 自动纳入回归，再提交 git（dev 分支）。

## 每个项目需要什么

| 文件 | 必需性 | 说明 |
|---|---|---|
| `<名字>.json` | 必需 | Export → JSON 的骨架数据 |
| `<名字>.atlas` | 建议 | 与 json 同名放同目录；Stage B 语义加载要用 |
| `<名字>.png` | 建议 | 视口阶段必需；只做数据回归可不带 |
| 导出设置备注 | 建议 | 编辑器精确版本号、Nonessential 勾否、Pretty print 勾否 |

命名沿用导出文件名即可（如 hero.json + hero.atlas），无需重命名。

## 优先级（先给这些）

1. **3.8 与 4.2 双版本各导一份的同一项目**（跨版本对照最值钱）
2. 项目里**最复杂**的骨架：linked mesh、蒙皮权重、IK/path、physics(4.2)、
   sequence(4.2)、多皮肤、deform 密集动画
3. Nonessential **开**一份（日常导出即可）；条件允许再补**关**的一份
   （默认值折叠语料，对 writer 的字段折叠规则很重要）
4. 数量起步：每个版本线 2~3 个；之后日常导出随手丢进来即可，越多越好

## 保密

语料只进本仓库（局域网内部工具），仅作回归测试输入，不做任何外发。

## 收到之后我会做什么

- 入 corpus + 跑 `npm test`（Stage A 结构零差异 / Stage B 双版本语义加载）
- 若有差异 → 修 writer，这正是 harness 存在的意义
- 更新 README 语料计数，并把结果同步给你
